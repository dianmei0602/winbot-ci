# winbot 0.3.0 收口实施计划

> **给执行者：** 按任务逐条做，用 `- [ ]` 勾进度；每个任务先写测试/自检，再改实现。

**目标：** 把 winbot 从「功能堆完了」收成一个可交付、可回归、可回溯的版本，不夸大没验证的能力。

**架构：** 不改现有分层（`src/` 主进程 + `src/dsh-plugins/` 注入 DSH 子进程 + `ui/` 原生 ESM + `electron/` 桌面壳）。收口只做：版本基线、回归入口、已知粗粝点、文档与发布物。

**技术栈：** Node 24 ESM、`node:sqlite`、DSH SDK over stdio、Electron 44.11.5 + electron-builder(NSIS)、ComfyUI 0.45（本机）。

**规格来源：** `docs/FEATURES.md`（功能与未做清单）、`PROGRESS.md`（逐轮记录）。

## 基线（2026-11-22 21:0x）

- 版本：`0.2.1`，安装版在 `%LOCALAPPDATA%\Programs\winbot`，后端 `:5178` 在线，ComfyUI `0.45.0` 在线。
- **没有 git 仓库**（`fatal: not a git repository`）——所有历史只在 `PROGRESS.md` 里，无法 diff/回滚。这是收口第一件事。
- 测试：`test/` 下 60 个脚本，其中 9 个单元/回归、9 个 UI/CDP、42 个一次性探针与生成验证混在一起，没有统一入口。
- 已知粗粝点：回复里带绝对路径；Slack/Discord 没有「被 @ 才回」；群聊认人靠字符串匹配；安装包 ~250 MB 未签名。
- 清单位置：`docs/FEATURES.md`（已做 / 未做 / 粗糙点）。

## 全局约束

- 不删除用户数据（`data/`、`%APPDATA%\winbot\data` 一律保留）。
- 不改 DSH 安装目录；所有定制只走本项目与生成的 patch。
- 生成能力（图/视频/3D）本机验证耗时长：默认回归**不包含**它们，单列为「慢验证」。
- 每条结论必须来自实际命令或代码，不写「应该可以」。
