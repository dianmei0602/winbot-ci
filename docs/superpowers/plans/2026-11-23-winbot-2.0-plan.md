# winbot 2.0 规划

> 可视化复盘：`docs/winbot-2.0-review.html`（43 条问题、能力自评、里程碑）

**目标：** 2.0 不追新功能，先把「能用一辈子」的四件事做掉：迭代闭环、可观测、边界（远程+权限）、扩展（连接器+语音）。

**基线（2026-11-23，0.6.0）：** 22 提交 / 14 个 release / 30 条回归（67 个测试文件）/ src 6838 行 / 安装包 250 MB（装后 948 MB）/ db 212 KB。

**架构：** 不变（`src/` 主进程 + `src/dsh-plugins/` 注入 DSH + `ui/` 原生 ESM + `electron/` 壳）；2.0 只做拆分与解耦，不换内核。

**技术栈：** Node 24 ESM、`node:sqlite`、DSH SDK over stdio、Electron 44.11.5、electron-builder(NSIS)、ComfyUI 0.45。

## 结论（复盘）

1. 功能面过了「够用」线，短板集中在可运维性（CI、更新闭环、诊断、远程）。
2. 最高杠杆是 CI + 自动更新闭环——它决定后续每个版本的成本。
3. 第二大杠杆是远程访问——它决定产品边界。

## 里程碑

### M1 可靠性 & 可运维（1-2 周）

- [x] CI 真正跑起来：公共镜像仓 winbot-ci 跑 Actions，四步全绿（2026-11-24）
- [x] 自动更新端到端实测：0.6.6 → 0.6.7 全自动（检查/下载/退出/安装/启动）
- [ ] 工具事件入库（`tool_calls` 表）：刷新/换设备仍能看到「谁、什么工具、多久、成没成」
- [ ] 诊断页 `/diagnostics`：版本、依赖、日志尾部、最近错误，一键导出 zip

**验收：** CI 绿 ✓；一次真实升级无需人工 ✓；诊断包能复现问题（未做）。docs/runbook-ci-release.md 记录流程与已知问题。

### M2 远程与安全（1-2 周）

- [ ] Tailscale 集成：检测客户端 → 一键 serve → 扫码
- [ ] 令牌轮换（旧链接失效）
- [ ] 工具级权限（按工具名开关）
- [ ] HTTPS：自签或反代方案

**验收：** tailnet 内手机可用；换令牌后旧链接 401；禁用的工具调不到。

### M3 生态与体验（2-3 周）

- [ ] OAuth 应用目录：GitHub / Slack / Notion / Google 四家
- [ ] 语音 STT/TTS（先做 Telegram 语音消息）
- [ ] 团队包导入/导出/示例集
- [ ] 多语言框架（zh/en）

**验收：** 4 家一键接入；语音可转写并回语音；切换语言生效。

### M4 可选（3 周+）

- [ ] 3D 贴图（Hunyuan paint，~6 GB）
- [ ] 3D 内嵌预览
- [ ] 移动端 PWA
- [ ] 云电脑（第三方）

## 架构改动

- 拆 `ui/app.js`（3204 行 → 6-8 个视图模块）
- `server.js` 路由模块化
- 版本化 migration 框架
- 依赖解耦：339 个 `@deepseek-ai` 包 + Electron 44.11.5 白名单强绑定，需评估升级路径

## 风险

| 风险 | 应对 |
|---|---|
| GitHub Actions 账单未通过 | 公共仓镜像 / 本地 runner，先跑同一套脚本 |
| 静默安装失败 | 0.5.3 已先退出再装；2.0 加安装回执与回滚 |
| Tailscale 需用户装客户端 | 检测未装时给一键下载说明，不强制 |
| OAuth 凭据安全 | 先 4 家、本机加密存储、权限最小化 |
| 拆文件引入回归 | 每拆一块补对应快检，CI 跑语法+单元 |

## 明确不做

云电脑、微信个人号、macOS/Linux 客户端、自建模型训练、Composio 全量 500 应用。
