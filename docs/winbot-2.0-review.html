winbot 复盘与 2.0 规划

一个能干活、能接渠道、能本机生成的个人 AI 机器人 —— 现在缺什么、怎么补
当前版本 0.6.0（安装版在跑） 复盘日期 2026-11-23 数据来自 git / 测试 / 实机探测

一、复盘结论 先看这个

1. 功能面已经过了「够用」线，短板全在可运维性。 群聊、渠道、生成、自动更新、手机访问都能跑；真正卡住日常的是 CI 起不来、自动更新没做过端到端实测、工具历史不入库、远程只能同 WiFi。

2. 最高杠杆是「CI + 自动更新闭环」，不是再加功能。 现在每次改动都要人工构建、手动装、手动回归；闭环一旦成立，后面每个版本的成本会掉一个数量级。

3. 第二大杠杆是远程访问。 只监听本机/局域网，决定它只能是「坐在电脑前用的工具」，而不是「随时找得到的机器人」。

五、还能做什么 能力缺口

已经有，但可以更深

  • 群聊协作：现在按名字路由，可加「角色/职责卡」和任务看板
  • 生成：长视频已有滑窗/接续，3D 仍无贴图
  • 技能：只有本地目录，可做技能市场/版本管理
  • 定时任务：单条执行，缺链式/依赖/失败重试
  • 记忆：只有「关于我」+ 每机器人 MEMORY.md，缺语义检索

还没有（按价值排序）

  • 远程访问（Tailscale/反代）—— 产品边界
  • 语音 STT/TTS —— 微信式体验的前提
  • 托管式应用目录（OAuth 一键）—— 对比 OpenMausBot 的最大差距
  • 工具级权限 —— 现在只有三档，不能禁单个工具
  • 多语言 / 3D 贴图 / 3D 内嵌预览 / 移动端 PWA

七、winbot 2.0 规划 主题：可靠 · 可远程 · 可扩展

2.0 不追新功能，先把「能用一辈子」的四件事做掉： 迭代闭环（CI + 更新）、可观测（诊断）、边界（远程 + 权限）、扩展（连接器 + 语音）。

工期：单人全职约 7 周；与 agent 并行约 3 周。每个里程碑都可独立交付、独立验收。

架构变化（2.0 必须动的地方）

  • 拆分 ui/app.js（3204 行 → 按视图拆 6-8 个模块），否则每加一个交互都在改同一个文件
  • server.js 路由模块化（现在 ~1000 行路由堆在一起的单文件）
  • 工具事件入库：新增 tool_calls 表，刷新/换设备也能看到「谁用了什么工具、多久、成没成」
  • 迁移框架：现在手工 migrate 函数，2.0 起用版本化 migration
  • 依赖解耦：339 个 @deepseek-ai 包 + Electron 44.11.5 强绑定，锁死升级路径

风险

风险应对
GitHub Actions 账单未通过先用公共仓镜像或本地 runner 跑同一套脚本；不等账单
静默安装失败（权限/占用）0.5.3 已改「先退出再装」；2.0 加安装结果回执与回滚
Tailscale 需要用户装客户端检测到未装时给一键下载 + 说明；不强制
OAuth 目录涉及第三方凭据先做 4 家、存本机加密文件，权限最小化
拆文件引入回归每拆一块补对应快检，CI 里跑语法+单元

2.0 明确不做

云电脑（付费第三方）、微信个人号（风控）、macOS/Linux 客户端（成本高、需求未验证）、 自建模型训练、Composio 全量 500 应用（只做 4 家精选）。

数据来源：本仓库 git 历史（22 commits / 14 tags）、docs/FEATURES.md、test/（67 个文件、30 条回归）、 本次实机探测（文件接口、安装队列、导出、备份/恢复、更新检查）与 GitHub check-run 注解。
